# Job Application Copilot — 正式设计规格

- 日期：2026-09-20
- 状态：待用户书面审阅
- 目标平台：macOS 13+
- 目标用户：单一用户、本机使用
- 现有项目：`JobApplicationWidget`

## 1. 产品定义

Job Application Copilot 是一个本地优先的 macOS 求职控制台。它同时承担两类职责：

1. 每天自动发现、验证和分析适合用户的职位；
2. 帮助用户追踪申请进度，并为高匹配职位生成真实、可审计的申请材料。

产品不是通用招聘平台，也不自动提交申请。Codex 负责需要语言理解和材料生成的步骤；本地 Worker 负责调度、数据流和可靠性；SwiftUI App、菜单栏与 Widget 负责展示和用户操作。

用户应能在五秒内回答：

- 今天有哪些值得申请的新职位？
- 哪些申请需要跟进或即将截止？
- 每个职位当前处于什么状态？
- 哪些 Resume 和 Cover Letter 已准备好？

## 2. 已确认的用户约束

- 搜索区域：Melbourne / Victoria 的现场或混合岗位，以及 Australia-wide remote。
- 工作类型：Full-time 优先。
- 目标方向：Data Analyst、BI Analyst、Insights Analyst、Data Scientist、AI/ML、Health/Medical Data 及相关岗位。
- 职级：Graduate、Junior、Entry-level 优先；Senior/Lead 若实际职责和用户经历匹配，也允许进入候选列表。
- 工作权利：用户是澳洲 Permanent Resident，拥有无限制工作权。
- 明确要求 Australian Citizen，或其安全许可必须基于公民身份的岗位不符合资格。
- 联邦岗位若接受 PR 则保留；条件不明确时标记待确认。
- 自动材料阈值：匹配度至少 85%。
- 每天 Melbourne 时区上午 8:00 后，在网络稳定时运行一次。
- 手动 Fetch 可随时强制执行一次。
- Outlook / Microsoft 365 的 `Deleted Items` 是职位提醒邮件的主要来源之一。
- 邮件访问只使用 Microsoft Graph `Mail.Read`；不发送、移动、恢复、删除邮件，也不改变已读状态。
- Apply 使用 Google Chrome 打开原始申请页面，不自动填写或提交。

## 3. 成功标准

产品达到可日用状态必须满足：

- 重启 App、重启电脑、断网、睡眠或运行中断都不会丢失申请数据。
- 每日任务在 8:00 时离线的情况下，能在之后网络稳定时补跑一次。
- 睡眠或休眠期间不运行 Worker、Codex CLI 或浏览器自动化。
- 相同职位在 SEEK、Indeed、LinkedIn 或邮件中重复出现时只显示一条记录。
- 任何导入或刷新都不能静默覆盖本地状态、备注或申请日期。
- 高风险、资格不符、职位关闭、需要未确认经历的岗位不得自动生成材料。
- Resume 不超过两页，Cover Letter 默认一页，且不包含未经验证的经历。
- App、菜单栏和 Widget 显示一致的职位数量、状态和刷新时间。
- 所有自动决策都能追溯到来源、规则、评分依据与使用的履历事实。

## 4. 非目标

第一版明确不包含：

- 自动填写或提交职位申请；
- 修改、删除或移动 Outlook 邮件；
- 绕过验证码、反自动化机制或网站访问控制；
- 云端账户系统、多用户、团队协作或跨设备同步；
- 在 App 内实现通用网页爬虫平台；
- 对职位真实性作百分之百保证；
- 无限量并发抓取或无限量自动生成申请材料；
- 以未经确认的聊天内容、代码或项目推断用户经历。

## 5. 系统架构

```text
Outlook Deleted Items ─┐
SEEK / Indeed / LinkedIn ├─> job-scout Worker ─> SQLite ─> SwiftUI App
公司官方招聘页面 ───────┘          │             ├─> Menu Bar
                                     │             └─> Widget
                                     ├─> Codex CLI
                                     └─> DOCX / PDF
```

### 5.1 组件职责

#### job-scout Worker

- 执行邮件读取、职位收集、页面解析、去重、开放状态检查、风险判断和资格判断；
- 调用 Codex CLI 完成语义匹配、事实对齐和材料生成；
- 对所有模型输出执行固定 Schema 验证；
- 使用事务写入 SQLite；
- 保存阶段 checkpoint，支持断网、睡眠或进程终止后恢复；
- 生成通知事件和 Widget 摘要。

#### 网络等待器

- 仅在当天 8:00 后任务待执行且当前离线时启动；
- 仅订阅 macOS 网络状态与睡眠状态；
- 不读取邮件、数据库业务内容，不启动 Chrome 或 Codex；
- 网络稳定后启动一次 Worker 并退出。

#### SwiftUI 主 App

- 展示、编辑和过滤职位；
- 管理申请状态、备注、日期和本地文件；
- 提供 Fetch、Apply、Mark as Applied、Archive 等操作；
- 展示同步进度、来源错误和需要用户确认的事项。

#### 菜单栏

- 展示今日高匹配职位、待跟进、即将截止和刷新状态；
- 提供 Fetch 和打开主窗口的快捷入口；
- 不承担完整编辑流程。

#### Widget

- 只读取已生成的摘要；
- 不执行搜索、网络请求、AI 调用或文件生成；
- 点击职位后打开 App 对应详情。

### 5.2 AI 执行方式

- 使用 Codex CLI 的 `codex exec`；
- 使用 ChatGPT Pro 登录，不使用 OpenAI API Key；
- 不产生独立 API 按量账单，但会消耗用户的 Codex 套餐额度；
- 登录失效或额度不足时停止 AI 阶段并通知用户；
- 不自动回退到收费 API；
- 提取与初筛使用轻量模型，复杂匹配和材料生成使用更强模型；
- Codex 输出必须是可验证的结构化数据，不能直接修改主数据库。

## 6. 调度、联网与睡眠状态机

```text
未到 8:00
    ↓
8:00 后且当天未成功
    ↓
网络离线 ──> 启动低功耗网络等待器
    ↓ 网络连续稳定 60 秒
执行两次轻量 HTTPS 连通测试
    ↓ 均成功
启动 Worker
    ↓
断网/睡眠 ──> 保存 checkpoint ──> 停止子进程 ──> 等待恢复
```

规则：

- `launchd` 仅负责每天 8:00 的日历触发与登录后启动检查，不配置每 15 分钟或其他固定间隔轮询；
- 唤醒补跑由 macOS 唤醒事件和 Worker 启动时的当天状态检查触发；
- 8:00 时有稳定网络则立即执行；
- 8:00 时离线则等待网络事件，不做固定间隔轮询；
- 网络必须连续可用 60 秒，并通过两次间隔数秒的轻量 HTTPS 测试；
- 短暂连网后再次断线会重新开始稳定计时；
- Mac 在 8:00 时关机或睡眠，登录或唤醒后检查当天状态并补跑；
- 不使用唤醒系统的 Power Assertion 或定时唤醒能力；
- 收到睡眠通知时停止 Codex CLI、浏览器自动化和网络任务；
- 唤醒后先重新确认网络稳定，再从 checkpoint 继续；
- Fetch 使用 force 模式，可绕过“当天已成功”条件，但不能绕过网络和睡眠检查；
- 文件锁防止自动运行和 Fetch 同时执行；
- 等待网络时 CPU 应接近 0%，不得有固定计时轮询或频繁 wake-up。

## 7. 数据模型与持久化

SQLite 是唯一可信数据库，位于 App Group，使用 WAL 模式支持 Worker 写入和 App/Widget 并发读取。

### 7.1 核心实体

#### Job

- 稳定内部 ID；
- 公司、职位、地点、工作方式、工作类型；
- 原始发布日期、截止日期、邮件收到时间；
- 规范化 URL、平台职位 ID、全部来源链接；
- JD 原文快照、内容指纹、最后验证时间；
- 开放状态；
- 诈骗风险、风险理由和验证证据；
- 工作资格结果与理由；
- 匹配分、匹配理由、满足项、缺口和证据；
- 主申请状态、备注、申请日期、下次行动日期；
- 创建、更新时间和归档时间。

#### SourceRecord

- 来源类型、平台职位 ID、原始 URL；
- 邮件 ID 或页面 ID；
- 首次和最后发现时间；
- 最近抓取状态和错误。

#### Document

- Job ID；
- Resume 或 Cover Letter；
- DOCX、PDF 路径和版本；
- 使用的 JD 快照和事实集合版本；
- 生成时间、状态和错误。

#### VerifiedFact

- 事实内容与分类；
- 来源文件、近期项目或对话；
- 是否已由用户确认；
- 首次确认和最后修改时间。

#### Run

- 自动或手动触发；
- 开始、结束和 checkpoint；
- 每个来源的成功、失败和错误；
- 新增、更新、跳过和生成数量。

### 7.2 数据规则

- 平台 ID、规范化 URL、公司/职位/地点以及 JD 指纹共同用于去重；
- 同一职位跨平台合并，但保留所有来源；
- 导入只更新来源数据，不能覆盖本地状态、备注、申请日期和用户文件；
- 发布时间和截止日期只有来源明确提供时才填写；
- 邮件收到时间单独存储，不冒充发布时间；
- 过期、拒绝和重复记录只归档，不自动永久删除；
- 每日成功运行后导出 JSON 备份，保留最近 30 份；
- 支持预览任意备份并恢复；
- 当前九条职位和 Westpac 的 Applied 状态必须迁移。

## 8. 职位收集与去重工作流

每次运行依次执行：

1. 使用 Graph `Mail.Read` 读取 `Deleted Items` 中尚未处理的职位提醒；
2. 以邮件 ID 去重并提取平台职位 ID、标题、公司和原始链接；
3. 执行 SEEK、Indeed、LinkedIn 的保存搜索，补充邮件未覆盖的职位；
4. 优先读取公开职位页面；
5. 页面必须登录或公开信息不足时，才启动独立的 Chrome Job Scout 配置；
6. 遇到验证码暂停该来源并通知用户，不尝试绕过；
7. 解析结果进入暂存区，完成 Schema 验证后再合并；
8. 生成材料前再次验证职位仍然开放。

浏览器访问采用低频、顺序执行。每个来源独立保存进度，一个来源失败不阻止其他来源。

## 9. 真实性与诈骗风险

系统输出三个风险级别：Low risk、Needs review、High risk。它们是风险评估，不是真实性保证。

检查依据：

- 来源是否为真实平台或公司官方招聘域名；
- 公司名称、官网、招聘页面和澳洲企业信息是否一致；
- 联系邮箱是否属于合理公司域名；
- 是否要求付款、购买设备、提供银行密码或转去 Telegram/WhatsApp；
- 薪资是否明显不合理；
- JD 是否疑似盗用、信息矛盾或缺少可验证雇主；
- 链接最终跳转目标是否异常。

处理规则：

- Low risk 可进入正常评分；
- Needs review 保留在审核区，等待用户判断；
- High risk 不生成材料、不自动打开链接，但不会被自动删除。

## 10. 资格与匹配评分

### 10.1 硬性资格

- Citizen-only 或必须基于公民身份取得的 clearance：不符合；
- 接受 PR：符合；
- 条件不明确：待确认；
- 职位已关闭：不符合；
- Senior/Lead 不自动排除，按真实职责和经历评分。

### 10.2 权重

- 技能与工具：35%；
- 工作职责：25%；
- 行业与项目经验：15%；
- 地点与工作方式：10%；
- 工作权利：10%；
- 职级差距：5%。

Codex 必须为每个得分提供来自 JD 和已验证经历的证据，并列出未满足的必选条件。资格不符合或缺少关键必选条件时，职位不能达到 85%。关键词重合本身不能构成高分。

## 11. 自动材料生成

自动生成必须同时满足：

- 匹配度至少 85%；
- Low risk；
- 工作资格符合；
- 原始 JD 已验证且职位仍开放；
- 不是重复职位；
- 不需要未经确认的新经历；
- 当天生成数量未超过五组。

### 11.1 事实来源

- `~/Desktop/resume_gpt` 中由用户指定的 Master Resume 是默认事实来源，也是定制 Resume 的输出根目录；
- `~/Desktop/cover letter gpt` 是 Cover Letter 输出根目录；
- 近期对话、代码或项目内容属于待验证事实；
- 使用待验证事实前，必须展示内容、来源和计划用途并获取用户确认；
- 事实确认一次后加入已验证经历库，之后可自动复用；
- 被拒绝的事实不得使用。

### 11.2 生成步骤

1. 冻结当前 JD 快照；
2. 选择与岗位有关的已验证事实；
3. 生成结构化 Resume 和 Cover Letter 草稿；
4. 检查虚构经历、无证据技能、遗漏必选条件和格式；
5. 生成不超过两页的 Resume 和默认一页的 Cover Letter；
6. 同时保存 DOCX、PDF 和生成说明；
7. 使用临时文件生成，全部成功后原子移动到正式位置；
8. 已存在文件使用 `v2`、`v3`，不覆盖用户手动修改版本。

目录结构：

```text
~/Desktop/resume_gpt/Company - Role/
  Resume - Company - Role.docx
  Resume - Company - Role.pdf

~/Desktop/cover letter gpt/Company - Role/
  Cover Letter - Company - Role.docx
  Cover Letter - Company - Role.pdf
```

## 12. 申请状态与操作

主状态：

```text
New -> Review -> Preparing -> Ready -> Applied
                                    |
                                    v
                              Interview -> Offer
                                   |
                                   v
                                Rejected

任意非活动状态 -> Archived
```

附加标记独立于主状态：

- Needs fact approval；
- Scam review；
- Eligibility unclear；
- Generation failed；
- Follow-up due；
- Expiring soon。

Apply 行为：

- 使用 Chrome 打开原始申请页面；
- 只记录打开事件，不自动标记 Applied；
- 用户点击 Mark as Applied 后记录申请日期；
- 默认七天后进入待跟进；
- 截止前三天提醒；
- 面试日期和自定义提醒可由用户设置。

## 13. 用户界面

### 13.1 主窗口

- 左侧：状态、来源、匹配度、风险和提醒过滤器；
- 中间：职位列表；
- 右侧：JD、评分证据、技能缺口、文件和进度详情；
- 列表显示公司、职位、来源、发布时间、截止日期、匹配度、风险和状态；
- 顶部提供 Fetch、搜索、排序和最近刷新结果；
- Fetch 显示当前阶段并允许在安全点取消。

### 13.2 菜单栏

- 今日高匹配职位；
- 待跟进、即将截止和等待确认；
- 当前刷新状态；
- Fetch 和打开主窗口。

### 13.3 Widget

- Small：高匹配数量、待跟进数量和刷新状态；
- Medium：优先级最高的三个下一步；
- Large：更多岗位、截止日期和快捷打开；
- 点击职位打开 App 对应详情；
- 修改数据后刷新 Widget timeline。

## 14. 通知策略

只在以下情况通知：

- 新增 85%+ 岗位；
- 需要确认新经历；
- 职位即将截止；
- 到达跟进日期；
- Outlook/Codex 登录失效、验证码或连续刷新失败；
- 自动材料生成完成或失败。

普通新增职位，以及成功但没有重要发现的刷新保持安静。

## 15. 安全与隐私

- Microsoft OAuth Token、Codex 凭据和浏览器敏感配置使用 macOS Keychain 或其原生安全存储；
- 邮件、JD 和网页全部视为不可信输入；
- 忽略外部内容中要求模型执行命令、改变规则或读取本地文件的指令；
- HTML 先移除脚本、隐藏文本和追踪参数；
- JD 内容不能被转化为 shell 命令；
- 可疑链接不自动打开；
- 日志不记录完整简历、OAuth Token、Cookie 或个人敏感内容；
- Chrome Job Scout 使用独立配置，只在必要时启动；
- 不绕过验证码或网站安全机制；
- App 不自动向外部网站提交数据。

## 16. 错误处理

- Outlook 登录失效：暂停邮件源并要求重新授权；
- Codex 登录失效或额度不足：停止 AI 阶段，不切换到 API；
- 网站验证码：暂停来源并要求人工处理；
- 单个职位解析失败：保留来源链接，其他职位继续；
- PDF 失败：保留草稿和错误，不产生正式损坏文件；
- 断网或睡眠：保存 checkpoint，停止子进程，恢复后继续；
- 所有来源失败：保留旧数据，不清空列表；
- 数据迁移失败：保留旧数据库并停止升级；
- 所有错误必须说明来源、阶段、自动重试状态和用户动作。

## 17. 首次设置流程

1. 检查 Codex CLI，并确认 ChatGPT Pro 登录；
2. 连接 Microsoft Graph，只授权 `Mail.Read`；
3. 从 `resume_gpt` 列出文件，由用户指定 Master Resume；
4. 确认 `cover letter gpt` 输出目录；
5. 建立独立 Chrome Job Scout 配置，并由用户完成必要登录；
6. 验证 App Group、SQLite、Widget 和 DOCX/PDF 转换环境；
7. 执行一次 Dry Run，只搜索、去重和评分，不生成材料；
8. 展示 Dry Run 结果，用户确认后启用自动调度。

## 18. 测试与验收

### 18.1 数据与业务逻辑

- 跨平台重复职位能够合并；
- 导入不会覆盖本地状态；
- 重复 ID、损坏 JSON 和缺失字段不会导致崩溃；
- Citizen-only 职位正确排除；
- High risk 职位不能生成材料；
- 未确认事实不能进入 Resume；
- 每日生成上限有效；
- 现有数据迁移后职位和 Applied 状态保持一致；
- JSON 备份可以预览并恢复。

### 18.2 网络与电源

- 短暂连网不会启动 Worker；
- 网络连续稳定并通过测试后只启动一次；
- 运行中断网可以保存并恢复；
- 睡眠、休眠和合盖进入睡眠时不运行；
- 等待网络时 CPU 接近 0%，无固定轮询和频繁 wake-up；
- Fetch 与自动任务不会并发执行。

### 18.3 文档

- Resume 不超过两页，Cover Letter 默认一页；
- PDF 文本可复制且链接有效；
- 模板格式符合 Master Resume；
- 文件生成失败不会覆盖旧版本；
- 生成说明能列出使用的事实和 JD 依据。

### 18.4 App 与 Widget

- App、菜单栏和 Widget 数据一致；
- Widget 不执行网络或 AI 操作；
- Apply 使用 Chrome 打开正确原始链接；
- Apply 不自动修改为 Applied；
- 键盘操作、基本 VoiceOver 标签和错误提示可用；
- 无签名开发构建和正式签名构建均通过；
- Bundle ID、App Group 和 Widget entitlement 正确。

## 19. 实施阶段

1. 修复现有工程身份、签名、App Group 和数据迁移；
2. 建立 SQLite、模型、事务、备份和核心测试；
3. 实现低功耗调度、网络稳定判断、睡眠处理和 checkpoint；
4. 接入 Microsoft Graph `Mail.Read`；
5. 实现职位收集、规范化、去重、开放状态、风险和资格判断；
6. 接入 Codex CLI，完成匹配分析与结构化输出验证；
7. 建立已验证事实库与 DOCX/PDF 生成；
8. 完成主窗口、申请进度和首次设置流程；
9. 完成菜单栏和 Widget；
10. 完成 Chrome 补充读取、能耗、安全、离线和恢复验收。

每个阶段必须先完成对应的最小自动化检查，再进入下一阶段。实现不得为了未来的多用户、云端或跨平台需求提前引入抽象。

## 20. 已锁定的设计决策

- 采用本地 Worker + SwiftUI 控制台；
- 采用 SQLite，不以 Excel 或 Markdown 作为主数据库；
- 使用 Outlook Graph 邮件只读权限；
- 使用 Codex CLI + ChatGPT Pro，不使用 API Key；
- 每日 8:00 后首次稳定联网运行；
- 使用事件驱动网络等待，不做 15 分钟轮询；
- 睡眠与休眠期间停止所有工作；
- 85% 是自动生成材料阈值；
- 每天最多自动生成五组材料；
- 生成 DOCX 和 PDF；
- 已确认事实可复用，未确认事实禁止使用；
- Apply 只打开 Chrome，不自动提交；
- 数据本地优先，失败时保留旧状态并可恢复。
